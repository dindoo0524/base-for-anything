# 오늘의 주문서

- 주문 제목: UI v1·v2 비교 경로 분리
- 날짜: 2026-08-12
- 작업 상태: 완료

## 오늘 만들 기능

현재 Bible Hunter UI를 v1으로 보존하고, 이후 UI 개선을 독립적으로 진행할 v2 경로를 만듭니다.

## 작업하는 이유

현재 잘 동작하는 화면을 유지하면서 새 UI를 개발하고 두 버전을 URL로 나란히 비교하기 위해서입니다.

## 구체적인 요청

- `/v1`에서 현재 UI를 볼 수 있게 합니다.
- `/v2`에서 v1과 같은 상태로 시작하는 별도 UI 컴포넌트를 볼 수 있게 합니다.
- `/`는 당분간 안정 버전인 v1을 표시합니다.
- 로그인과 프로필 조회 로직은 세 경로에서 공통으로 사용합니다.
- v1과 v2는 같은 Supabase 회원, QT, 댓글 데이터를 사용합니다.
- 이후 v2 스타일은 v2 전용 범위에서 수정할 수 있게 루트 클래스를 구분합니다.

## 이번에는 하지 않을 작업

- v2 디자인 변경
- 데이터베이스 테이블 복제
- v1과 v2의 회원 또는 데이터 분리
- 배포 주소 변경

## 완료 조건

- `/`, `/v1`, `/v2`가 모두 열립니다.
- `/`와 `/v1`은 현재 안정 UI를 표시합니다.
- `/v2`는 독립 컴포넌트에서 시작합니다.
- 세 경로에서 기존 Supabase 로그인 세션을 사용합니다.
- lint와 build가 통과합니다.

## 작업 후 사용자가 확인할 내용

- 로그인 상태에서 `/v1`과 `/v2`를 각각 엽니다.
- 두 경로에 같은 QT 데이터가 보이는지 확인합니다.
- v1 화면이 기존 화면과 같은지 확인합니다.

## Codex 작업 결과

- 현재 Bible Hunter UI를 `BibleHunterV1` 컴포넌트로 복사해 보존했습니다.
- 이후 UI 개선용 `BibleHunterV2` 컴포넌트를 별도 파일로 분리했습니다.
- `/v1`과 `/v2` 라우트를 추가하고 `/`는 안정 버전인 v1에 연결했습니다.
- 세 경로의 Supabase 환경 확인, 로그인, 프로필 조회 로직을 공통 서버 컴포넌트로 옮겼습니다.
- v1과 v2의 최상위 요소에 `app-v1`, `app-v2` 클래스를 각각 추가해 이후 v2 스타일을 범위 지정할 수 있게 했습니다.
- 두 버전은 같은 Supabase 회원, QT, 댓글 데이터를 사용합니다.
