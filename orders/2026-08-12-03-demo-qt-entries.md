# 오늘의 주문서

- 주문 제목: 이번 달 임시 QT 묵상 데이터 추가
- 날짜: 2026-08-12
- 작업 상태: 완료

## 오늘 만들 기능

지정한 테스트 계정의 2026년 8월 현황을 확인할 수 있도록 지난 날짜의 임시 QT 묵상 여러 건을 추가하는 SQL을 준비합니다.

## 작업하는 이유

대시보드, 날짜별 비교와 댓글 화면을 실제 사용에 가까운 데이터로 확인하기 위해서입니다.

## 구체적인 요청

- 2026년 8월 1일부터 10일까지 임시 묵상 10건을 준비합니다.
- 날짜별 성경 본문은 `daily_scriptures`에 등록된 값을 사용합니다.
- 이미 작성한 날짜의 묵상은 덮어쓰지 않습니다.
- 임시 묵상에는 식별 가능한 표시를 넣어 나중에 테스트 데이터만 삭제할 수 있게 합니다.
- 계정 이메일이 Git에 포함되지 않도록 seed와 정리 SQL은 Git 제외 파일로 만듭니다.

## 이번에는 하지 않을 작업

- 실제 작성된 QT 기록 수정 또는 삭제
- 다른 사용자 계정에 테스트 데이터 추가
- 앱 화면이나 RLS 정책 변경

## 완료 조건

- 대상 계정의 빈 날짜에만 임시 묵상이 추가됩니다.
- 각 묵상은 DB의 50~100자 제한을 만족합니다.
- 테스트 데이터만 지우는 정리 SQL이 함께 제공됩니다.
- 계정 이메일과 임시 SQL이 Git 상태에 나타나지 않습니다.

## 작업 후 사용자가 확인할 내용

- Supabase SQL Editor에서 seed SQL을 실행합니다.
- 앱을 새로고침하고 8월 현황과 날짜별 묵상을 확인합니다.
- 테스트가 끝나면 필요한 경우 정리 SQL을 실행합니다.

## Codex 작업 결과

- 대상 테스트 계정의 2026년 8월 1일부터 10일까지 임시 묵상 10건을 추가하는 seed SQL을 작성했습니다.
- `daily_scriptures`의 날짜별 본문을 사용하며, 이미 QT가 있는 날짜는 덮어쓰지 않게 했습니다.
- 각 묵상에 `[수업 테스트]` 표시를 넣어 실제 작성 데이터와 구분했습니다.
- 같은 계정, 같은 기간, 같은 표시를 가진 테스트 묵상만 삭제하는 정리 SQL을 작성했습니다.
- 계정 이메일이 들어간 두 SQL 파일은 `.gitignore`의 `.env*` 규칙으로 Git에서 제외했습니다.

## 변경한 파일

- `orders/2026-08-12-03-demo-qt-entries.md`
- `supabase/.env.local-seed-demo-entries.sql` (Git 제외)
- `supabase/.env.local-cleanup-demo-entries.sql` (Git 제외)

## 실행 및 검증 결과

- 임시 묵상: 10건 확인
- 묵상 길이: 각 60~66자로 DB 제한 50~100자 충족
- 기존 날짜 처리: `on conflict (author_id, entry_date) do nothing`
- 계정 이메일이 포함된 SQL의 Git 제외 상태: 확인
- Git 공백 오류 검사: 통과

## 남아 있는 문제

- Supabase SQL Editor에서 seed SQL을 실행해야 실제 데이터가 추가됩니다.
- 기존 기록과 날짜가 겹치면 해당 날짜는 안전하게 건너뛰므로 실제 추가 건수는 10건보다 적을 수 있습니다.
- 정리 SQL로 테스트 QT를 삭제하면 그 QT에 달린 테스트 댓글과 답글도 외래 키 설정에 따라 함께 삭제됩니다.
