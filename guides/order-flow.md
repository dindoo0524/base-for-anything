# 오늘의 주문 인터뷰 진행 방법

사용자가 `오늘의 주문서를 작성할게요.`라고 말하면 이 순서를 따릅니다.

1. 앱 코드를 수정하지 않습니다.
2. `AGENTS.md`, `PROJECT_BRIEF.md`, `orders/`의 기존 주문서를 확인합니다.
3. 종이에 적은 내용을 한꺼번에 입력해도 된다고 먼저 안내합니다.
4. 이미 입력한 내용은 다시 묻지 않고, 빠졌거나 모호한 중요한 내용만 한 번에 하나씩 질문합니다.
5. 요청을 하나의 작은 작업으로 정리합니다. 범위가 크면 첫 번째 완료 단위만 제안합니다.
6. 주문서 초안을 채팅에 먼저 보여주고 확인받습니다.
7. 승인 전에는 주문서 파일과 앱 코드를 수정하지 않습니다.
8. 승인 후 날짜별 주문서 파일을 생성하되, 바로 구현하지 않고 작업 요청을 기다립니다.

## 파일명과 상태

- 로컬 시스템 날짜의 `YYYY-MM-DD-순번-짧은-영문-작업명.md` 형식을 사용합니다.
- 같은 날짜 파일을 확인하여 `01`, `02`, `03` 순번을 붙입니다.
- 작업명은 짧은 영문 kebab-case로 Codex가 정합니다.
- 상태는 `작성 중`, `작업 요청`, `완료`만 사용합니다.

## 승인 후 구현

사용자가 `이 주문서대로 작업해주세요.`라고 말하면 가장 최근에 승인한 주문서를 찾습니다. 대상이 불분명할 때만 파일명을 한 번 질문합니다. 상태를 `작업 요청`으로 바꾸고 주문서의 한 가지 작업만 구현합니다. `PROJECT_BRIEF.md`와 충돌하면 먼저 확인합니다. lint, build, 가능한 실제 동작 확인을 마친 뒤 결과와 변경 파일, 검증 결과, 남은 문제를 같은 주문서에 기록합니다. 검증 성공 시 상태를 `완료`로 바꾸고 멈춥니다.
