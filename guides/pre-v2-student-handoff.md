# 나민숙님 전달용: v2 UI 작업 전 수정사항

## 이 문서의 목표

나민숙님이 마지막으로 작업한 `010eab1` 이후 무엇이 바뀌었는지 이해하고, 기존 작업을 잃지 않은 상태에서 수정본을 노트북에 적용하는 것이 목표입니다.

이번 기준점은 다음과 같습니다.

```text
010eab1  나민숙님 마지막 작업
   ↓
5da8adf  날짜별 본문·입력 화면·댓글 권한 수정
   ↓
7a0dade  v1·v2 UI 경로 분리
```

`7a0dade`가 실제 v2 디자인을 시작하기 전 앱 기준점입니다.

## 먼저 설명할 한 문장

> 기존 화면과 회원·댓글 기능을 버린 것이 아니라, Supabase에 맞게 데이터 저장과 권한을 정리하고 현재 UI를 v1으로 보존한 뒤 v2 작업 공간을 따로 만들었습니다.

## 수정사항 설명

| 기존 문제 | 원인 | 수정 내용 | 확인 방법 |

## 로그인 유지 방식

로그인은 localStorage가 아니라 Supabase Auth 세션 쿠키로 유지됩니다.

- 같은 기기와 같은 브라우저에서는 새로고침하거나 브라우저를 다시 열어도 로그인 상태가 유지됩니다.
- 로그아웃, 쿠키 삭제, 시크릿 모드, 세션 취소 시에는 다시 로그인해야 합니다.
- `.env.local`을 지우는 것은 로그인 데이터 삭제가 아니라 앱의 Supabase 연결 정보를 지우는 것입니다.

## 수강생 노트북에서 기존 작업 보존하기

코드를 가져오기 전에 프로젝트 폴더의 터미널에서 아래 명령을 실행합니다.

```bash
git status
git log -1 --oneline
```

`git status`에 수정 파일이 보이면 pull하지 말고 먼저 멈춥니다. 수정 파일이 없고 마지막 커밋이 `010eab1`이면 기존 작업에 기준 태그를 붙입니다.

```bash
git tag student-baseline-010eab1 010eab1
```

이 태그는 수정 전 상태로 돌아가야 할 때 사용하는 안전 표지입니다.

## 수정본 가져오기

강사 컴퓨터에서 현재 변경을 GitHub의 `origin/main`에 push한 뒤, 수강생 노트북에서 실행합니다.

```bash
git switch main
git pull --ff-only origin main
npm ci
```

`--ff-only`는 예상하지 못한 별도 히스토리가 있을 때 자동으로 섞지 않고 멈추게 합니다. 오류가 나면 강제로 덮어쓰지 않습니다.

적용 후 커밋을 확인합니다.

```bash
git log -3 --oneline
```

목록에 `7a0dade`와 `5da8adf`가 보이면 코드 전달이 완료된 것입니다.

## 새 Supabase 연결 전 준비

Git으로 전달되는 것:

- 앱 코드
- SQL migration `001`~`006`
- 월별 본문 관리 안내
- v1·v2 경로

Git으로 전달되지 않는 것:

- `.env.local`
- Supabase URL과 Publishable key
- Auth 회원 계정
- 기존 QT와 댓글 데이터
- 강사 컴퓨터의 임시 테스트 seed SQL

따라서 새 Supabase 프로젝트를 만든 뒤 수강생 노트북에서 새 `.env.local`을 직접 작성해야 합니다. 이 작업은 다음 수업 단계에서 진행합니다.

## 연결 후 확인할 주소

```text
http://localhost:3000/     안정 버전 v1
http://localhost:3000/v1   안정 버전 v1
http://localhost:3000/v2   UI 개선 작업 버전
```

현재 v1과 v2는 같은 모습이며 같은 Supabase 데이터를 사용합니다. 이후 디자인 변경은 `components/bible-hunter.tsx`와 `.app-v2` 범위에서만 진행합니다. `components/bible-hunter-v1.tsx`는 수정하지 않습니다.

## 기능 확인 체크리스트

- [ ] 새 계정으로 회원가입할 수 있다.
- [ ] 로그아웃 후 이메일과 비밀번호로 로그인할 수 있다.
- [ ] 브라우저를 다시 열어도 로그인 상태가 유지된다.
- [ ] 오늘 날짜의 성경 본문이 자동 입력된다.
- [ ] 자동 입력된 성경 범위를 직접 수정할 수 있다.
- [ ] 50~100자의 묵상을 저장할 수 있다.
- [ ] 새로고침 후 저장한 QT가 다시 보인다.
- [ ] 본인 묵상에 일반 댓글을 작성할 수 있다.
- [ ] 다른 계정이 묵상에 댓글을 작성할 수 있다.
- [ ] 묵상 작성자가 다른 사람의 댓글에 한 단계 답글을 작성할 수 있다.
- [ ] `/v1`과 `/v2`에서 같은 데이터가 보인다.

## 아직 해결됐다고 말하면 안 되는 항목

아래 항목은 현재 코드에 남아 있으므로 Vercel 공개 배포 전에 결정해야 합니다.

1. 로그인한 일반회원도 기존 `/admin` 주소에 접근할 수 있습니다.
2. 가입한 모든 사용자가 하나의 전체 그룹으로 묶여 서로의 묵상을 봅니다.
3. 기존 `/admin`, `/login`, `entries` 기능이 Bible Hunter와 함께 남아 있습니다.
4. 다른 사람이 남긴 새 댓글은 실시간으로 나타나지 않아 새로고침이 필요합니다.

첫 버전을 가족과 제한적으로 사용할 계획이라면, 최소한 기존 관리자 화면을 제거하고 필요한 계정을 만든 뒤 공개 회원가입을 닫는 방식을 권장합니다. 가족별 그룹 분리는 별도 작업으로 남깁니다.

## 강사가 수업 시작 때 읽어줄 내용

> 지난 시간의 마지막 커밋은 그대로 보존했습니다. 오늘은 그 위에 날짜별 말씀 DB, 9월 자동 전환, 내 글 댓글 권한, v1·v2 화면 분리를 적용합니다. 코드를 받은 다음 새 Supabase 프로젝트를 만들고 연결하며, 두 계정으로 전체 흐름을 확인한 뒤 Vercel 배포 여부를 결정하겠습니다. 문제가 생기면 강제로 덮어쓰지 않고 `student-baseline-010eab1` 기준점으로 돌아갈 수 있습니다.
